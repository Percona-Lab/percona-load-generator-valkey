Server Basic

One address for a standalone server, as valkey://host:port or host:port. For a cluster list one or more nodes (comma separated): plgv finds the rest, routes every command by its key's slot, and splits the results per node. For sentinel list the sentinels and give the master name; plgv follows the master through failovers. Multi-key commands in a cluster need hash tag groups (Advanced, Dataset details). Credentials are not entered here: set PLGV_USERNAME and PLGV_PASSWORD in the environment before starting plgv web.

Dataset Basic

Server metrics Basic

Server metrics: Also reads statistics from the Valkey server during the run, so the results can explain why performance changed, not just what plgv measured. Once per interval (default 1 second) plgv sends three read-only commands: INFO (memory, hits and misses, evictions, connections), SLOWLOG GET (commands the server found slow) and LATENCY LATEST. It never changes server settings or clears logs. Cost: a few extra commands per second. Needs permission to run those commands. Off by default.

Save and load run settings Basic

Seed and deterministic traffic Advanced

Deterministic traffic: the same seed, operation budget and workload always send the same commands, and the run reports a traffic fingerprint that proves it. It needs a seed and a budget, one worker count for the whole run, and refuses operations that depend on the clock or on server replies (PUBLISH, XCONSUME, WATCH_INCR, {now}). Off by default. With a budget, the run ends when the operations are sent, not after the duration.

Pipelining and pacing Advanced

Closed loop: each worker sends its next batch when the previous one finishes, so a slow server slows the load down. Open loop: batches arrive at the target rate whether or not the server keeps up. Latency then includes the time a batch waited to be sent, and batches that never got sent are counted as dropped. The open loop needs a target rate.

Pipeline depth sends that many operations per round trip (each is charged the batch time). With a target rate, coordinated-omission latency is measured from each batch's intended start, so a stall shows its full delay. It needs a target rate.

Load profile Advanced

A profile changes how many workers are active over time. Fixed uses Workers under Run. Pacing a changing number of workers with a target rate needs the open loop.

Stages

Sweep Advanced

A sweep runs the same workload several times, once per level, and stores each as its own run. By worker count shows how throughput and latency change as concurrency grows and where more workers stop helping. By target rate shows where the server stops keeping up. Duration is the length of each run. Results appear in Compare Runs.

Pub/Sub subscribers Advanced

Add PUBLISH (or SPUBLISH when sharded) to the workload and set subscribers above 0: each subscriber listens to every channel, so each message is delivered once per subscriber. plgv measures the time from publishing to receipt and counts messages that never arrive. With 0 subscribers it only publishes.

Raw commands Advanced

Run your own Valkey commands as the workload. One per line, optionally starting with a weight (5 GET {key}). Placeholders: {key} or {key:hash} (a random existing key), {value}, {n} (a key number), {int:1-100}, {now}. Quote text with spaces. Lines starting with # are ignored.

Blocked by default: commands that can delete data, change the server or stop it, such as FLUSHALL, FLUSHDB, SHUTDOWN, DEBUG, CONFIG SET, CLIENT KILL, CLUSTER FAILOVER, SCRIPT FLUSH, REPLICAOF. Tick the box only for a server you can afford to lose. Commands that would break plgv's own connections (MULTI, SELECT, SUBSCRIBE, blocking commands) are never allowed: use the TXN, WATCH_INCR, BRPOP and Pub/Sub operations instead.

Encryption (TLS) Advanced

Files, not secrets: the fields hold file paths on the machine running plgv; keys and passwords are never stored in settings. The user name and password come from PLGV_USERNAME and PLGV_PASSWORD. A valkeys:// address also turns TLS on. Skipping verification removes the protection against a man in the middle: use it for throwaway tests only.

Key-space analysis Advanced

Key-space analysis: When the run ends, plgv samples keys on the server with SCAN and reads each one's type, size (MEMORY USAGE), expiry (PTTL) and length. The Key Space tab shows the types, sizes, expiry and the biggest keys, and the Insights tab warns about big keys. It only reads, never changes data, and runs after the measured part, so it does not affect the results. In a cluster every primary is scanned. Cost: a few commands per inspected key, on the server for a few seconds. Off by default.

Dataset details Advanced

With hash tag groups above 0, every key carries a {group} tag, so keys of one group share a cluster slot and MGET/MSET work in a cluster. 0 means no tags (a cluster then refuses multi-key commands, which would fail with CROSSSLOT).
